# Example requests

Invented firms only. Each line: the request → what the module does.

- "Сделай условия для интернет-магазина Example Home SRL: товары для дома, доставка курьером по Молдове и Румынии"
  → facts, both regimes, the checkpoints that fit (C15 delivery and risk, C6 only the goods exceptions that apply),
  terms from the common core and the goods block, a list for the web developer.
- "Сделай условия продажи для онлайн-курсов Example Courses SRL, покупатели в Молдове и Румынии" → facts (live or
  recorded, access start), both regimes, the checkpoints, terms from the course block and model M03 in the document
  language; the privacy notice handed to `legal-privacy` if it is on.
- "Мы продаём подписку на приложение Example App, с пробным периодом. Как сделать проще всего и законно?" →
  configuration: options (access at once with consent, trial then paid, monthly or yearly) with cost, risk and
  verdict; C16 for renewal and ending; one recommended option.
- "Продаём через маркетплейс, нужны ли свои условия?" → C17: what the marketplace already covers, what the seller
  must add, nothing duplicated.
- "Verificați termenii magazinului nostru online" → audit: checkpoint table with rules and fixes, real tracked
  changes in the user's DOCX, clean copy.
- "Покупатель через 10 дней просит вернуть деньги за записанный курс, доступ уже был" → withdrawal: was the
  prior consent and acknowledgement given and confirmed (C6)? Conditional answer, the deciding fact named; a reply
  drafted, the user sends it.
- "Do we need the new withdrawal button on our Romanian site?" → C7 on the task date, who provides it, what the
  site must show; the sanction from the act in force.
- "Клиент пожаловался в защиту прав потребителей" → complaint: the rule behind each claim, the lawful position, a
  draft reply; the user files it.
